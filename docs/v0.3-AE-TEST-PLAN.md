> item #1 ("Comprehensive AE0–AE11 envelope test suite"). The existing
> 9-test smoke suite covers the wedge; this doc scopes ~50 additional
> tests across 12 groups + a session breakdown + a per-group blocker
> list so any future Claude Code session can pick up a chunk
> independently.

> `test/AgentEnvelope.test.js` covering AE1.1-AE1.4, AE2.2, AE3.1-AE3.2,
> AE4.1-AE4.2. **Note:** existing AE2 was scoped against the old EIP-712

## Group detail

### AE0 — Pre-flight + scaffold (3 tests)

Establishes that the deploy is sane before AE1+ runs.

- **AE0.1** — `factoryAuthorityEverGranted` chain works: BCF is
  authorized on LST without 48h wait (scaffold-time bootstrap).
  Mirror-reads the bid path to confirm.
- **AE0.2** — BCF + EA + VIP all wired to each other (BCF →
  `vipSubscription`, EA → `bcf`).
- **AE0.3** — Stash deploys for the test EOA (Alice) via factory,
  with `getStashOf(alice)` returning a non-zero address.

### AE1 — Envelope CRUD + tier-table enforcement (6 tests)

Extends the existing 4 with edge cases.

- **AE1.1** *(exists)* — owner creates envelope; appears in state with
  stored caps.
- **AE1.2** *(exists)* — duplicate agentKey rejected with
  `EnvelopeAlreadyExists`.
- **AE1.3** — `AgentKeyIsContract` rejection: try to register a
  contract address as agent → reverts.
- **AE1.4** *(exists)* — `cancelEnvelope` removes agent from active
  list.
- **AE1.5** — recreate after cancel: cancel + immediate re-create same
  agentKey works (tombstone behavior).
- **AE1.6** — owner-only gating: non-owner `createEnvelope` reverts
  `CallerNotAuthorized`.

### AE2 — msg.sender authentication (5 tests) — REWRITE

Old AE2 was EIP-712 / signature verification. After `0e6eaba`'s
auth pivot, auth is `msg.sender == envelope.agentKey`. Replace
existing AE2.2 entirely.

- **AE2.1** — happy path: agent EOA submits `createBid` via stash
  with populated `AgentAuth`; bid registers; envelope budget
  consumed.
- **AE2.2** *(rewrite)* — wrong `msg.sender`: random EOA submits with
  an AgentAuth tuple naming the legit agent's address → reverts
  (envelope-side check `msg.sender == envelope.agentKey` fails).
- **AE2.3** — `EMPTY_AUTH` from non-owner: random EOA passes
  `EMPTY_AUTH` (claiming owner path) → reverts (LST/BCF owner-path
  check fails).
- **AE2.4** — `EMPTY_AUTH` from owner: stash owner passes
  `EMPTY_AUTH` → works (no envelope state touched).
- **AE2.5** — `reasoningTopicId` round-trips into events
  (`BidCreated`, `EnvelopeBudgetConsumed`).

### AE3 — Tier-cap enforcement at create (5 tests)

Requires fresh VIP per session so Alice can be moved through tiers.

- **AE3.1** — Free tier: `createEnvelope` reverts
  `TierDoesNotPermitEnvelopes`.
- **AE3.2** — Bronze tier: 1 slot allowed; 2nd envelope reverts
  `TierCapExceeded(1, 1)`.
- **AE3.3** — Silver tier: dailyHbarCap exceeded → reverts
  `InvalidEnvelopeParams` (caps come from BCF tier table; exceeding
  rejected at create).
- **AE3.4** — Gold tier: 3 envelopes allowed; 4th rejected.
- **AE3.5** — Tier downgrade grandfather: create 2 envelopes at
  Silver; let subscription expire to Free; existing envelopes still
  work for the rest of their expiresAt window; new envelope creation
  blocked.

### AE4 — Per-tx budget caps (4 tests)

Uses a Bronze stash with explicit small caps to make boundaries
testable in a single session.

- **AE4.1** — `perTxHbarCap` enforced: bid for `cap + 1` reverts
  `PerTxCapExceeded(attempted, cap, false)`.
- **AE4.2** — `perTxLazyCap` enforced: bid for `cap + 1` reverts
  `PerTxCapExceeded(attempted, cap, true)`.
- **AE4.3** — at-cap boundary: bid for exactly `cap` succeeds.
- **AE4.4** — zero per-tx cap: setting cap to 0 effectively disables
  the action (every action reverts).

### AE5 — Daily budget consumption (4 tests)

Within a single UTC day — no timing wait required.

- **AE5.1** — daily HBAR consumption accumulates across multiple
  actions on the same day.
- **AE5.2** — daily HBAR exhaustion: when remaining < attempted,
  reverts `BudgetExhausted(needed, remaining, false)`.
- **AE5.3** — daily LAZY consumption / exhaustion (symmetric).
- **AE5.4** — `EnvelopeBudgetConsumed` event carries correct
  `remainingHbar` + `remainingLazy` after each consumption.

### AE6 — Pause / kill-switch race conditions (5 tests)

- **AE6.1** — `pauseAgent(agent, true)` blocks subsequent actions:
  agent's next call reverts `EnvelopeAuthFailed(agent, Paused)`.
- **AE6.2** — `pauseAgent(agent, false)` re-enables.
- **AE6.3** — `pauseAllAgents(true)` blocks all agents; owner path
  (EMPTY_AUTH) still works.
- **AE6.4** — `pauseAllAgents` then `pauseAgent`: per-agent pause
  state independent of global flag.
- **AE6.5** — pause during in-flight: queue tx as agent, owner pauses
  in same Hedera consensus window; verify tx ordering behavior is
  consistent (timestamp ordering means whichever lands first wins —
  no race, just sequential).

### AE7 — Multi-envelope isolation (4 tests)

Requires Platinum tier on Alice + 3+ agent EOAs.

- **AE7.1** — 3 envelopes on one stash, each consumes independent
  budgets (agent A consumes its daily; agent B's daily is untouched).
- **AE7.2** — kill switch on agent A doesn't affect agent B.
- **AE7.3** — cancel envelope A doesn't affect envelope B's storage.
- **AE7.4** — `activeEnvelopeCount` accurate through CRUD churn.

### AE8 — Allowed-actions bitmap (5 tests)

Each `ActionType` (BidCreate, BidCancel, TradeExecute, TradeList,
TradeCancel, Arbitrage, AuctionCreate, AuctionBid, AuctionBuyNow)
should be independently gateable.

- **AE8.1** — `allowedActions = (1 << BidCreate)` permits createBid,
  rejects all others with `ActionNotAllowed`.
- **AE8.2** — bitmap with all 9 bits set permits everything.
- **AE8.3** — empty bitmap rejects everything.
- **AE8.4** — bitmap update via `updateEnvelopeCaps` (if it exists,
  else via cancel+recreate).
- **AE8.5** — auction-side actions (AuctionCreate/Bid/BuyNow) honor
  bitmap on the EA side via the stash forward.

### AE9 — Cross-vector flows (4 tests)

Both BCF and EA must honor envelope state.

- **AE9.1** — BCF flow: agent createBid → cancelBid; both consume
  budget (or whichever model is right per envelope semantics).
- **AE9.2** — EA flow: agent createAuctionListing → placeAuctionBid;
  both check envelope budgets atomically.
- **AE9.3** — agent paused on stash → both BCF and EA forwards revert
  uniformly.
- **AE9.4** — envelope expired (past `expiresAt`) → both surfaces
  revert `EnvelopeAuthFailed(agent, Expired)`.

### AE10 — Self-trade-via-agent gate (3 tests)

The agent path must NOT enable self-trade where the EOA path blocks
it.

- **AE10.1** — Alice's agent tries to execute Alice's own bid → must
  revert the same way Alice directly executing would (via
  `_resolveBeneficialOwner`).
- **AE10.2** — Bob's agent (where Bob's stash is the seller) tries
  to execute Bob's own trade → same revert.
- **AE10.3** — agent-initiated arbitrage where `bid.user ==
  trade.seller` → must revert (existing `executeArbitrage`
  self-arbitrage block).

### AE11 — Timing-gated tests (4 tests) — `RUN_TIMING_TESTS=1`

Real-time waits. Gate via env var so default runs skip these.

- **AE11.1** — daily counter reset: consume budget, wait until UTC
  midnight (`block.timestamp / 86400` increments), next action
  resets `consumedHbarToday` to 0 and works.
- **AE11.2** — multi-day cycle: 3-day consumption pattern, verify
  per-day reset works across multiple boundaries.
- **AE11.3** — envelope expiry: create with `expiresAt = now + N`,
  wait N seconds, next action reverts `EnvelopeAuthFailed(agent,
  Expired)`.
- **AE11.4** — VIPSubscription expiry → tier downgrade grandfather
  cycle (overlaps AE3.5 but for a longer real-time horizon).

## Per-session blockers

### Always required

- Fresh `VIPSubscription` deploy per test session — Alice's tier
  state persists across runs on the cached VIP contract. Without a
  fresh VIP, AE3 (tier caps) will reuse residual tier and miss the
  boundary conditions.
- A throwaway operator with ≥300 HBAR (the full suite is ~50 tests;
  each test costs ~1-3 HBAR in deploys + sends).
- ED25519 operator key (the tests use both the operator's Hedera
  account and several ECDSA agent EOAs).

### Session-specific

- **Session 1 (AE0-AE3, ~15 tests, ~25 min)** — fresh VIP + 1 agent
  EOA. No timing. ~50 HBAR.
- **Session 2 (AE4-AE7, ~17 tests, ~30 min)** — fresh VIP + 3
  agent EOAs. No timing. ~80 HBAR.
- **Session 3 (AE8-AE10, ~12 tests, ~25 min)** — fresh VIP + 2
  agent EOAs + a live EA auction setup. No timing. ~60 HBAR.
- **Session 4 (AE11, 4 tests, gated, hours of real-time)** —
  `RUN_TIMING_TESTS=1` only. Schedule during low-activity period.
  ~20 HBAR (only a few txs, but each separated by real-time waits).

Total budget across all sessions: ~210 HBAR; ~80 min runtime
(sessions 1-3 in same day; session 4 separately).

## File layout proposal

Split the existing single `test/AgentEnvelope.test.js` into:

```
test/
  AgentEnvelope.test.js         ← existing smoke (9 tests, stays)
  AgentEnvelopeFull.test.js     ← AE0-AE10 expanded (~48 tests)
  AgentEnvelopeTiming.test.js   ← AE11 timing-gated (4 tests)
```

Smoke stays for quick-iteration during contract changes (~2 min
runtime). Full suite is pre-mainnet only. Timing suite is on-demand.

The two new files share `scaffold.js` helpers (lifted from the
smoke file) so deploy logic isn't duplicated.

## Open design decisions

These need answers before session 1 starts. Most can be deferred to
"first instance running this finds out" but worth flagging:

1. **`updateEnvelopeCaps` existence**: AE8.4 assumes an update path
   exists. If only cancel+recreate works, drop AE8.4 or rephrase.
   Check `BidderContract.sol` for the API.
2. **Auction-side action consumption semantics**: does
   `placeAuctionBid` consume envelope budget in tinybars-bid-amount,
   or just authorize the call? AE4 tests assume the former. Verify.
3. **Tier downgrade grandfather time horizon**: AE3.5 mentions
   "existing envelopes still work for the rest of their expiresAt
   window" — confirm `getEnvelope(agent)` doesn't re-check VIP tier
   on each action (per design doc: tier is captured at create-time,
   then envelope is immutable until cancel/expiry).
4. **Agent-EOA-as-Hedera-account**: the tests need each agent EOA to
   be a real Hedera account that can SIGN+SUBMIT transactions. ED25519
   only works if the agent account is ED25519; ECDSA only if ECDSA.
   The runtime uses ECDSA more naturally (ethers Wallet). Confirm
   agent EOAs are created with ECDSA keys during scaffold.

## Resume-from-here

When picking up a session:

1. Pull v0.3, read this doc, pick a session number (1-4) from the
   table above.
2. Verify `.env` has all the prereqs from the existing test file
   header (lines 14-20).
3. Comment out `VIP_SUBSCRIPTION_CONTRACT_ID` to force fresh deploy.
4. Run the full sweep for that session's groups:
   ```bash
   npx hardhat test test/AgentEnvelopeFull.test.js --grep "^AE[0-3]"
   ```
   (Adjust the grep per session — `^AE[4-7]`, `^AE[8-9]|^AE10`, etc.)
5. Land code in chunks, never push the whole 48 in one commit.

When session 4 (timing) runs:
```bash
RUN_TIMING_TESTS=1 npx hardhat test test/AgentEnvelopeTiming.test.js
```
