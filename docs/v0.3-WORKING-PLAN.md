## Roadmap — next candidates

Ranked by my read on impact-to-effort. Pick from this list as priorities
shift; nothing is locked in.

### Tier 1 — substantial new surface

#### EnglishAuction contract — SHIPPED ✅
- **State:** Multi-agent design review complete (6 agents, May 2026).
  Implementation underway. Original design at `docs/EnglishAuction-DESIGN.md`
  amended per the review findings (see consensus log below).
- **Scope locked for v1 (user-decided post-review):**
  - Min duration 1h, max duration 7 days
  - Anti-snipe: 10 min window, 10 min extension, 24h total extension cap
  - Reserve price: in. Public.
  - **Buy-now price: in.** (Product agent recommended out; user overrode.)
  - **Bundle auctions: in, Tier C.** Up to 10 items per auction in
    any mixture of NFTs (across collections) and fungible tokens
    (e.g., 2× Gen2 + 1× LSM + 10k $LAZY in a single auction).
    `cryptoTransfer` precompile batches escrow / settle / cancel in
    one subcall per direction; subcall budget stays under 50 even
    fully loaded. Royalty handling: per-NFT-collection snapshot at
    create, paid manually at settle. (Product agent recommended out;
    user overrode.)
  - $LAZY auctions fee-free (preserve tokenomics rule)
  - Settle bounty: 10 bps default
  - Tier snapshot at create (prevents game-the-LSH-dump-before-settle)
  - **Royalty: manual at settle**, snapshot receiver + bps at create
    via `getTokenCustomFees(token)`. Avoids cryptoTransfer auto-royalty
    fragility on multi-step custody flows.
- **Consensus design changes from original 563-line doc:**
  - F1: Pull-payment fallback for seller proceeds (push fails brick auction)
  - F2: NFT transfer to winner wrapped in try/catch; `claimAuctionNFT` for failures
  - F3: Beneficial-owner resolution (mirror LST `setBcf` + `_resolveBeneficialOwner`)
  - F4: `nonReentrant` everywhere + explicit per-auction balance tracking
  - F5: Anti-snipe extension capped at 24h from `originalCloseAt`
  - F6: Manual royalty at settle (above)
  - F7: Snapshot `sellerTierAtCreate` (uint8) in Auction struct
  - F8: `pause(bool)` gating createAuction + placeBid
  - F9: Pull-payment bounty (same brick-on-revert risk as F1)
  - F10: Repack `Auction` struct to 5 slots (uint96 amounts, drop redundant fields)
  - A1: `bytes32 agentKey` on placeBid + BidCreated event
  - A2: `createAuctionOnBehalfOfStash` for future agent envelope flow
  - A3: `uint256[20] __gap` storage gap
  - A4: BCF reference + setBcf 48h timelock
  - A5: `getAuctionSnapshot`, `getClaimable`, `currentTimestamp` views
  - A6: Reserved `agentKey`/`agentReasoningTopicId` on all lifecycle events
  - A7: Cold-start metadata on close events (hard-delete on settle)
  - Naming: `BidPlaced` → `BidCreated`, merge `AuctionFailed` into `AuctionSettled(success)`,
    merge `claim*()` → `claim(PaymentToken)`, `NoRefundOwed` → `NothingToClaim`
- **No agent envelope blocker:** `agentKey` is a placeholder field
  emitted as bytes32(0) in v0.3. Agent envelope enforcement is upstream
  of placeBid (in BCF + agent runtime), not in the auction contract itself.
- **Estimate:** 13–15 KiB after F+A additions + buy-now + multi-serial.
- **Dependencies:** consumes LSHTierLib (settlement fee tier). Optional
  VIPSubscription consumer if tier-driven auction features are added.

#### Agent envelopes on BCF
- **State:** designed inline in `docs/AGENT-MARKETPLACE-DELTA.md` +
  `docs/AGENT-MARKETPLACE-PICKUP.md`; not yet specified to
  implementation-grade detail.
- **Estimate:** larger than EnglishAuction; touches BCF + stash impl +
  off-chain agent runtime.
- **Dependencies:** consumes VIPSubscription for tier-driven limits
  (agent slots, daily budget caps).
- **Why later:** the integration depth is higher and the design isn't
  yet fully spec'd. Better to ship EnglishAuction first as a known-
  scope piece, then tackle agent envelopes with clearer requirements.

### Tier 2 — supporting infrastructure

#### SDK package — `@lazysuperheroes/marketplace-sdk`
- **State:** not started.

  TypeScript helpers).
- **Why important:** flagged in the runbook as "the highest-leverage

  repo building on the marketplace has to re-derive ABIs and helper
  functions. Agentic-layer repo can't start without it.

#### LSHTierLib in LazyTradeLotto
- **State:** deferred because LazyTradeLotto is already on mainnet.
- **Path:** re-vendor `LSHTierLib.sol` into the lotto repo when the
  next lotto redeploy window opens, OR extract `LSHTierLib` to an npm
  package and consume it both places.
- **Recommendation:** npm package — also serves the SDK above.

### Tier 3 — debt and polish

These are flagged in `docs/v0.3-OPS-RUNBOOK.md §7`. Track but don't
prioritize ahead of Tier 1/2.

- **`LDRDegraded` event** in `_safeGetDelegatedLength`. Requires
  view→non-view refactor; the library's try/catch already handles the
  silent-downgrade case for staking.
- **`agentKey` parameter threading** on `createBid` / `cancelBid` /
  `executeAgainstBid` / `executeArbitrage`. Event schema is already
  locked (Phase 3); function signature change ships with agent
  envelope work.
- **Full rename of `contracts/legacy/HederaTokenService.sol` symbol**
  to `LegacyHederaTokenService` (~120 in-file refs across 4 legacy
  files). Currently mitigated by a warning banner.
- **Other owner-only functions under 48h timelock.** `setBcf` is
  timelocked; `authorizeFactory`, fee setters, protocol-profit
  withdraws are still instant. Decide consistently (timelock all, or
  document why setBcf is special) before mainnet.

### Tier 4 — operational

- **BCF migration runbook** documented in §2 of the ops runbook but
  not exercised. Needs a snapshot-and-replay tool for the new BCF's
  `stashOwnerOf` mapping if we ever swap factories.
- **LazyTradeLotto scanner cutover.** Document the off-chain scanner
  update before BCF mainnet activation. Required for lotto credits to
  route to humans (not stashes).
- **`/ultrareview`** on the full v0.3 branch when ready for mainnet.
  Multi-agent cloud audit. Mentioned earlier as a planned step.

## Conventions reminders

- **Run a single test file** when iterating:
  `npx hardhat test test/BidderContractFactory.test.js`.
- **Top up test accounts** between runs:
  `node scripts/testing/fundTestAccount.js 0.0.X <hbar>`.
  Pull from SCOOP accounts via
  `node scripts/testing/refillOperator.js 0.0.SCOOP <keyIdx> <hbar>`.
- **Force fresh LST deploy** by commenting
  `LAZY_SECURE_TRADE_CONTRACT_ID` in `.env`. Other reused IDs
  (BCF impl/factory, LAZY token, LGS, LDR) are uncached by default.
- **Bytecode budget is tight** for LST (~365 B headroom). Any new LST
  surface must come with an equivalent extraction OR live in BCF /
  new contract. See `LSHTierLib-DESIGN.md` §"Contingency" for the
  fallback pattern (deploy library as a contract, lose inlining, save
  bytecode in consumers).

## How to resume after a break

1. Read this file + `docs/v0.3-OPS-RUNBOOK.md`.
2. Run `git log --oneline -15` to see the latest commits.
3. Check uncommitted changes: `git status`.
4. Refill operator if test runs have drained it:
   `node scripts/testing/refillOperator.js 0.0.1310 2 800` (or any
   SCOOP account + matching key index from .env).
5. Run the relevant test suite (single file) to confirm baseline:
   `npx hardhat test test/BidderContractFactory.test.js`.
6. Pick a Tier 1 candidate from the roadmap above and start designing
   /implementing.
