## Agent envelopes on BCF — SHIPPED ✅

### Headline

Per-stash agent authorization with daily HBAR + LAZY budget caps,
EIP-712 signed actions, ECDSA recovery via `ecrecover` precompile,
tier-driven limits from BCF (48h timelock per tier), VIP-tier gating
at envelope creation. End-to-end functional on Hedera testnet.

### Decisions locked

- **Envelope storage**: on the stash via statically-linked
  `AgentEnvelopeLib`. Security finding H3 ruled against BCF placement.
- **Authentication model**: **msg.sender-only**. Hedera's protocol
  layer verifies the agent's tx signature (ECDSA secp256k1 OR ED25519,
  native to the agent account's key type) before the EVM runs.
  Contracts check `msg.sender == envelope.agentKey`. No EIP-712, no
  ecrecover, no nonce. Works uniformly for both Hedera key types.
- **Contract addresses rejected** at envelope creation via
  `extcodesize > 0` guard. Required because contracts can be called
  by anyone, propagating msg.sender. Documented as `AgentKeyIsContract`
  error.
- **Daily reset**: UTC midnight floor (`block.timestamp / 86400`).
- **Envelope state mutation**: lives on the stash via `spendForAgent`.
  Authorized callers are `factory` and `englishAuction` (both
  trust-rooted contracts in this codebase). Both BCF and EA call
  back `spendForAgent` to consume budget and validate state.
- **VIP lookup**: at envelope-create time only — never per action.
  Minimizes hot-path subcall cost.
- **Tier downgrade behavior**: grandfather. Existing envelopes run to
  their own expiry; new envelope creation blocked at the lower tier.
- **Tier limits semantics**: per-envelope, not per-stash. A user with
  N envelopes has N × per-envelope daily exposure. Documented in
  ops runbook §9.

### Locked default tier table (BCF-stored, owner-tunable via 48h timelock)

| Tier | Slots | Daily HBAR | Daily LAZY | Per-tx HBAR | Per-tx LAZY |
|------|-------|------------|------------|-------------|-------------|
| Free | 0 | — | — | — | — |
| Bronze | 1 | 500 | 5,000 | 200 | 2,000 |
| Silver | 2 | 1,500 | 15,000 | 500 | 5,000 |
| Gold | 3 | 3,500 | 35,000 | 1,000 | 10,000 |
| Platinum | 5 | 10,000 | 100,000 | 2,500 | 25,000 |

LSH-holder-gets-1-free-slot is a product/UX rule, not currently
enforced on-chain (the on-chain tier-cap table is keyed by paid VIP
tier only). Surface it at the SDK layer.

## Outstanding / deferred work

Ordered by priority. None of these block the v0.3 commit; they're
follow-up items for subsequent merges or pre-mainnet.

### Deferred from agent envelope work

1. **LST `authorizeFactory` 48h timelock** (security finding H3) —
   scoped + drafted but reverted because LST is at 23.636 KiB and the
   timelock impl adds +0.67 KiB, pushing it over 24 KiB. **Primary
   H3 mitigation is already in place**: envelopes live on the stash,
   `spendForAgent` verifies signature + budget per action regardless
   of which factory calls. The timelock is defense-in-depth for an
   owner-key compromise that bypasses operational multisig + timelock.
   Requires LST surface trim (~0.7 KiB) first.

2. **EnglishAuction `AgentAuth` threading** on `createAuction` /
   `placeBid` / `buyNow`. The `agentKey` event placeholders are
   already in shape from C.1; function signatures still take the old
   `bytes32 agentKey`. Thread `AgentAuth calldata` + integrate
   `spendForAgent` callback on the auctioneer's stash, same pattern
   as BCF.

3. **Comprehensive envelope test suite (AE0–AE11, ~60 tests)** —
   current 9 tests cover the smoke path. Comprehensive coverage
   (signature replay corner cases, daily reset timing, multi-day
   budget cycles, multi-envelope kill-switch isolation, cross-vector
   self-trade via signed agent action) needs:
     - A fresh `VIPSubscription` deploy per test session so Alice's
       tier is predictable.
     - `RUN_TIMING_TESTS=1` gate for the day-rollover tests (Hedera
       testnet can't fast-forward `block.timestamp`).
     - End-to-end signed-action coverage once an agent runtime exists
       to produce + submit signatures against real bids.

4. **AE1.3 (tier-cap exceedance) test** — scoped to Bronze (cap=1) but
   currently blocked by Alice's residual Platinum tier on the cached
   VIPSubscription. Lands with #3 above.

## Conventions reminders

- **Run a single test file** when iterating:
  `npx hardhat test test/BidderContractFactory.test.js`.
- **Top up test accounts** between runs:
  `node scripts/testing/fundTestAccount.js 0.0.X <hbar>`.
  Pull from SCOOP accounts via
  `node scripts/testing/refillOperator.js 0.0.SCOOP <keyIdx> <hbar>`.
- **Force fresh LST deploy** by commenting
  `LAZY_SECURE_TRADE_CONTRACT_ID` in `.env`. Required when the cached
  LST has a stale `bcf` pointer from an earlier session (symptoms:
  P5.20 + P5.23 fail with `_resolveBeneficialOwner` returning the
  stash address instead of the human owner).
- **`EMPTY_AUTH` for legacy-path test calls** — import from
  `utils/agentSigning.js`. Every `createBid` / `cancelBid` /
  `executeAgainstBid` / `executeArbitrage` / `cancelTradeFromStash` /
  stash-side `createTrade` needs it appended unless exercising the
  signed-agent path.
- **Bytecode budget reminders:**
  - LST: 23.636 KiB / ~365 B headroom. Any new LST surface must come
    with an equivalent extraction OR live in BCF / new contract.
  - BidderContract: 20.994 KiB / ~3 KiB headroom. CREATE2-clone
    invariant means any size change shifts every predicted stash
    address — see `LSHTierLib-DESIGN.md` §"Contingency" for fallback
    patterns.
