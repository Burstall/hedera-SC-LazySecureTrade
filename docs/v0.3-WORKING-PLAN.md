## Agent envelopes — SHIPPED ✅

### Headline

Per-stash agent authorization with daily HBAR + LAZY budget caps,
**msg.sender-only authentication** (no EIP-712, no ecrecover — Hedera's
protocol layer already validates the agent's tx signature, supports
ECDSA AND ED25519 native key types), tier-driven limits from BCF
(48h timelock per tier), VIP-tier gating at envelope creation. End-to-end
functional on Hedera testnet. Wedge complete across BCF bid/trade/arbitrage
**AND** EnglishAuction surface.

### Decisions locked

- **Envelope storage**: on the stash via statically-linked
  `AgentEnvelopeLib`. Security finding H3 ruled against BCF placement.
- **Authentication model**: **msg.sender-only**. Hedera's protocol
  layer verifies the agent's tx signature (ECDSA secp256k1 OR ED25519,
  whichever the agent's Hedera account uses). Contracts check
  `msg.sender == envelope.agentKey`. No EIP-712, no ecrecover, no
  nonce. Works uniformly for both Hedera key types.
- **Contract addresses rejected** at envelope creation via
  `extcodesize > 0` guard (`AgentKeyIsContract` error). Required
  because contracts can be called by anyone, propagating msg.sender.
- **Daily reset**: UTC midnight floor (`block.timestamp / 86400`).
- **Envelope state mutation**: lives on the stash via `spendForAgent`
  (factory-only) for BCF flows. EA flows use stash-side entry points
  that call `AgentEnvelopeLib.verifyAndConsume` directly (no roundtrip).
- **EA stays passive on auth**: receives `AgentAuth` for event
  attribution only. Stash forwards to EA with stash funds; envelope
  check happens on the stash side BEFORE the forward.
- **VIP lookup**: at envelope-create time only — never per action.
- **Tier downgrade behavior**: grandfather. Existing envelopes run to
  their own expiry; new envelope creation blocked at the lower tier.
- **Tier limits semantics**: per-envelope, not per-stash. Documented
  in ops runbook §9.

### Locked default tier table

Wired via `scripts/interactions/wireAgentTierLimits.js` post-deploy.
First call per tier is INSTANT; subsequent rotations are 48h timelocked.

| Tier | Slots | Daily HBAR | Daily LAZY | Per-tx HBAR | Per-tx LAZY |
|------|-------|------------|------------|-------------|-------------|
| Free | 0 | — | — | — | — |
| Bronze | 1 | 500 | 5,000 | 200 | 2,000 |
| Silver | 2 | 1,500 | 15,000 | 500 | 5,000 |
| Gold | 3 | 3,500 | 35,000 | 1,000 | 10,000 |
| Platinum | 5 | 10,000 | 100,000 | 2,500 | 25,000 |

LSH-holder-gets-1-free-slot is a product/UX rule, **not enforced on-chain**.
Surface at the SDK layer.

### Architecture summary

- **BidderContract (stash)** holds envelope state + does verification.
  Entry points:
  - `createEnvelope` / `cancelEnvelope` / `pauseAgent` / `pauseAllAgents`
    / `setVipSubscription` / `setEnglishAuction` (owner-only)
  - `createBid` / `cancelBid` / `createTrade` (owner OR agent path) —
    forward to BCF
  - `createAuctionListing` / `placeAuctionBid` / `buyNowAuction`
    (owner OR agent path) — forward to EA
  - `spendForAgent` (factory-only) — callback for BCF-mediated flows
- **BidderContractFactory** holds the tier table + dispatch helper.
  Functions take `AgentAuth` and callback `spendForAgent` on the
  stash when agent path is active.
- **EnglishAuction** takes `AgentAuth` for event attribution only.
  Passive on auth — the stash side did the envelope check.

## SDK v0.1 — SHIPPED ✅

### Headline

`@lazysuperheroes/marketplace-sdk` v0.1 lives under `packages/sdk/`
(standalone, root `package.json` untouched). Transport primitives only;
write-path builders + mirror helpers deferred to v0.2 once the agent
runtime exists to drive their shape.

### What's exported

- **ABIs** for the 5-contract v0.3 surface (LST, BCF, BidderContract,
  EnglishAuction, VIPSubscription) — auto-extracted from `artifacts/`
  by `scripts/copyAbis.js`, wired as `prebuild`.
- **Address registry** per network — testnet populated, mainnet null.
  Both Hedera id and EVM long-zero forms per contract.
- **Ethers Interface factories** (lazy) — for calldata encode, return-
  data decode, event topic computation, log parsing.
- **AgentAuth helpers** — `EMPTY_AUTH`, `buildAgentAuth`,
  `AGENT_AUTH_TUPLE_TYPE` (TS port of `utils/agentAuth.js`).
- **Typed enums** — `BidStatus`, `BidValidityCode`, `AuctionState`,
  `PaymentToken`, `ActionType`, `AuthFailCode`, `VipTier`, `LshTier`.
  Numeric values verified against Solidity sources. `VipTier` and
  `LshTier` are deliberately different enums (different Silver values).
- **Typed structs** — `BidDetails`, `AgentEnvelope`, `EnvelopeParams`,
  `TierLimits`, `Trade`, `TokenSerialPrice`, `AuctionItem`,
  `RoyaltyInfo`, `AuctionSnapshot`, `AuctionParams`.

### Build

```
cd packages/sdk
yarn install   # only tsup + typescript; peers come from consumer
yarn build     # → dist/ (CJS 181KB + ESM 180KB + .d.ts dual)
yarn typecheck # tsc --noEmit, clean
```

`prebuild` calls `copy-abi`, so `yarn build` is single-command "fresh
ABIs + clean compile". Fails loudly if any of the 5 artifacts is
missing — run `yarn hardhat compile` at repo root first.

### Decisions locked

- **Location**: `packages/sdk/` standalone (matches Farms repo
  precedent — that repo also has standalone packages, not a yarn
  workspace).
- **Scope discipline**: v0.1 is transport primitives only. No write-
  path TransactionRequest builders, no mirror helpers. Both deferred
  to v0.2 because the agent runtime is the consumer that should drive
  their shape, and that runtime doesn't exist yet.
- **Mainnet addresses**: `null` placeholder until v0.3 mainnet deploy
  lands. Bumping SDK to 1.0.0 then.

## Known gotchas (operational)

These bit us during F.8 testnet validation. Read before re-running.

1. **Cached LST has stale `bcf` pointer.** When BCF code changes (ABI
   or behavior), the cached LST's `bcf` field still points at the OLD
   factory. New `setBcf(newFactory)` enters 48h timelock-queue mode
   (because `bcf != 0`) and DOESN'T apply. Symptom: P5.20 + P5.23 fail.
   **Fix:** comment out `LAZY_SECURE_TRADE_CONTRACT_ID` in `.env` to
   force fresh LST deploy. Add it back after the run succeeds.

2. **Test accounts deplete mid-run.** BCF test scaffold tops Alice +
   Bob to 200 HBAR each; the full suite consumes ~150-180 HBAR per
   account. P5.4+ tests cascade with `INSUFFICIENT_PAYER_BALANCE`.
   **Fix:** before any BCF run, top up to 300+ HBAR each:
   ```
   node scripts/testing/fundTestAccount.js 0.0.8986332 250
   node scripts/testing/fundTestAccount.js 0.0.8986333 250
   ```

3. **VIP-tier residual state.** Alice's `VIPSubscription` state
   persists across test sessions on the cached VIP contract. AE1.3
   (tier-cap exceedance) was scoped for Bronze (cap=1) but Alice's
   residual tier is Platinum (cap=5) — test deferred until comprehensive
   suite ships fresh VIP per session.

4. **`hardhat compile` artifacts cache.** When refactoring contracts
   that change ABI, force fresh deploy by uncaching the impl + factory
   in `.env`. Hardhat picks up source changes but won't redeploy if
   the contract ID is set.

5. **EA gas estimation flakes.** `[gas:placeBid] estimation failed`
   warnings are routine; fallback values work fine. No action needed.

6. **Stash bytecode is at 23.260 KiB (740 B headroom).** Any new
   stash surface in v0.4 needs the same care that landed G.1 — extract
   to a library, drop redundant features, or move logic to BCF.
