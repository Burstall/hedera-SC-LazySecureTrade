## Overview

v0.3 introduces a three-contract stack for CLOB-style NFT bidding on Hedera:

```
LazySecureTrade (LST)         -- existing marketplace (single/batch trades, fees, royalties)
BidderContractFactory          -- central router: bid registry, arbitrage engine, stash deployer
BidderContract (per-user)      -- "stash": holds user funds, executes trades on their behalf
```

### What v0.3 Adds

- **Per-user stash contracts**: each user gets a dedicated contract clone that holds their HBAR, $LAZY, and NFTs. Stashes are non-upgradeable by design; users always retain withdrawal sovereignty.
- **CREATE2 deterministic addressing**: every stash address is derivable off-chain from the user's EVM address alone. No RPC call needed to know where a user's stash lives.
- **CLOB-style bidding**: users place bids on NFT collections (or specific serials). Sellers can accept bids directly. Bids have explicit lifecycle states (Active, Cancelled, Executed, Expired).
- **Arbitrage**: third parties can match underpriced open-market LST trades against resting bids, capturing the spread. Self-arbitrage is blocked. Profit splits between the arbitrageur and the protocol.
- **Paginated discovery**: all view functions are bounded; serial-level queries use cursor-based pagination. `getStashSnapshot` aggregates stash state in one call.

### Hedera-Specific Design Facts

- **No MEV**: Hedera consensus orders transactions by timestamp. There is no mempool, no front-running, no sandwich attacks. The arbitrage system has no commit-reveal or cooldown mechanics because none are needed.
- **50 subcalls per transaction**: every HTS precompile call counts against this ceiling. Batch sizes are deliberately conservative.
- **~1M gas per new token association**: budget for this when the stash first interacts with a new NFT collection.
- **CREATE2 cannot pre-fund on Hedera**: you can predict the stash address but cannot send HBAR to it before the stash contract is deployed.
- **5-second mirror node lag**: after a consensus transaction, expect up to 5 seconds before the mirror node REST API reflects the new state.

## Quick Start

This walkthrough deploys a stash, funds it, creates a bid, accepts a bid, and withdraws -- end to end.

### Prerequisites

```bash
npm install ethers @hashgraph/sdk
```

```js
const { ethers } = require("ethers");
const { Client, AccountId, PrivateKey, Hbar, ContractExecuteTransaction,
        ContractCallQuery, TransferTransaction } = require("@hashgraph/sdk");

// Hedera testnet setup
const operatorId = AccountId.fromString(process.env.ACCOUNT_ID);
const operatorKey = PrivateKey.fromStringED25519(process.env.PRIVATE_KEY);
const client = Client.forTestnet().setOperator(operatorId, operatorKey);

// Contract addresses (replace with your deployment)
const FACTORY_ADDRESS = "0x...";
const LST_ADDRESS = "0x...";

// ABIs (extract from artifacts after compile)
const factoryAbi = require("../abi/BidderContractFactory.json");
const stashAbi = require("../abi/BidderContract.json");
const lstAbi = require("../abi/LazySecureTrade.json");
```

### Step 1: Deploy a Stash

```js
// Anyone can deploy a stash for any user -- the owner is always `user`
const deployTx = new ContractExecuteTransaction()
    .setContractId(FACTORY_ADDRESS)
    .setGas(1_500_000)
    .setFunction("deployStash");

const deployResult = await deployTx.execute(client);
const deployRecord = await deployResult.getRecord(client);

// The stash address is in the StashDeployed event
console.log("Stash deployed at:", deployRecord.contractFunctionResult.getAddress(0));
```

### Step 2: Fund the Stash

```js
// Predict stash address off-chain (no RPC needed)
const stashAddress = getStashAddressOffChain(operatorId.toSolidityAddress());

// Send HBAR directly to the stash
const fundTx = new TransferTransaction()
    .addHbarTransfer(operatorId, new Hbar(-10))
    .addHbarTransfer(AccountId.fromSolidityAddress(stashAddress), new Hbar(10));

await fundTx.execute(client);
```

### Step 3: Create a Bid

```js
// Call createBid on the stash (only the owner can call this)
const iface = new ethers.Interface(stashAbi);
const createBidData = iface.encodeFunctionData("createBid", [
    "0xNFT_TOKEN_ADDRESS",  // target NFT collection
    [],                      // empty = any serial in collection
    ethers.parseUnits("5", 8), // 5 HBAR in tinybars (500_000_000)
    0,                       // no $LAZY component
    0,                       // no expiry (bid lives until cancelled)
    0                        // minAcceptablePrice: 0 = accept any trade price in arbitrage
]);

const bidTx = new ContractExecuteTransaction()
    .setContractId(stashAddress)
    .setGas(800_000)
    .setFunctionParameters(Buffer.from(createBidData.slice(2), "hex"));

await bidTx.execute(client);
```

### Step 4: Seller Accepts the Bid

```js
// Seller calls executeAgainstBid on the factory
// The seller must have approved the LST contract for the NFT
const execData = new ethers.Interface(factoryAbi).encodeFunctionData(
    "executeAgainstBid",
    [bidId, nftTokenAddress, serialNumber]
);

const execTx = new ContractExecuteTransaction()
    .setContractId(FACTORY_ADDRESS)
    .setGas(1_200_000)
    .setFunctionParameters(Buffer.from(execData.slice(2), "hex"));

await execTx.execute(client);
// NFT is now in the bidder's stash; HBAR was paid to the seller
```

### Step 5: Withdraw NFT from Stash

```js
// The stash owner withdraws the NFT to their own account
const withdrawData = new ethers.Interface(stashAbi).encodeFunctionData(
    "withdrawSingleNFT",
    [nftTokenAddress, serialNumber]
);

const withdrawTx = new ContractExecuteTransaction()
    .setContractId(stashAddress)
    .setGas(600_000)
    .setFunctionParameters(Buffer.from(withdrawData.slice(2), "hex"));

await withdrawTx.execute(client);
```

## Stash Management

### Deploying a Stash

Two entry points:

| Function | Caller | Notes |
|---|---|---|
| `deployStash()` | The user themselves | Convenience wrapper for `deployStashFor(msg.sender)` |
| `deployStashFor(address user)` | Anyone | Permissionless. Useful for gasless onboarding relays or agent-initiated setup. The stash owner is always `user`. |

Both revert with `StashAlreadyExists` if the user already has a stash.

### Off-Chain Address Prediction

The stash address is deterministic. You can compute it off-chain without any RPC call:

```js
const { ethers } = require("ethers");

function predictStashAddress(factoryAddress, implementationAddress, userAddress) {
    const salt = ethers.solidityPackedKeccak256(
        ["bytes12", "address"],
        ["LST_STASH_v1", userAddress]
    );

    // OZ Clones.predictDeterministicAddress formula
    const initCodeHash = ethers.solidityPackedKeccak256(
        ["bytes"],
        [
            ethers.concat([
                "0x3d602d80600a3d3981f3363d3d373d3d3d363d73",
                implementationAddress,
                "0x5af43d82803e903d91602b57fd5bf3"
            ])
        ]
    );

    return ethers.getCreate2Address(factoryAddress, salt, initCodeHash);
}
```

Or query the on-chain view:

```js
const stashAddress = await factory.getStashAddress(userAddress);
```

Use `getStashOf(user)` to check whether the stash has actually been deployed (returns `address(0)` if not).

### Funding the Stash

- **HBAR**: send a `TransferTransaction` directly to the stash address.
- **$LAZY**: ERC-20 transfer to the stash address. The stash must be associated with $LAZY (this happens automatically during `initialize()`).
- **NFTs**: the stash receives NFTs when bids are executed. To deposit NFTs manually, approve an NFT allowance to the stash, then call a transfer (or use `associateToken` + direct HTS transfer).

### Withdrawing from the Stash

| Function | What | Notes |
|---|---|---|
| `withdrawHbar(amount)` | HBAR | Keeps 1 HBAR minimum balance in stash for gas |
| `withdrawLazy(amount)` | $LAZY | Standard ERC-20 transfer to owner |
| `withdrawSingleNFT(token, serial)` | Single NFT | Uses 1-tinybar custody hop |
| `withdrawNFTs(tokens, serials, hbarAmounts)` | Batch NFTs | Up to 8 serials per token via `batchMoveNFTs` |

## Bid Lifecycle

### Creating a Bid

Bids are created by calling `createBid` on the stash. The stash validates funds, auto-associates the target NFT collection, increments its nonce, and routes to the factory.

Parameters:

| Param | Type | Description |
|---|---|---|
| `token` | `address` | Target NFT collection |
| `serials` | `uint256[]` | Specific serials to bid on. Empty array = any serial in the collection. |
| `hbarAmount` | `uint256` | HBAR bid amount in tinybars |
| `lazyAmount` | `uint256` | $LAZY bid amount (XOR with hbarAmount -- use one or the other) |
| `expiry` | `uint256` | Unix timestamp. 0 = no expiry. |
| `minAcceptablePrice` | `uint256` | Floor tinybar price for arbitrage protection. 0 = accept any trade price. Set this to guard against junk-NFT surprise matches. Cannot exceed `hbarAmount`. |

The factory assigns `BidStatus.Active` and indexes the bid for discovery.

### BidStatus Enum

```
None       (0) -- struct default; bid never existed
Active     (1) -- live, eligible for execution and arbitrage
Cancelled  (2) -- explicitly cancelled by the bidder
Executed   (3) -- matched against a seller (executeAgainstBid or executeArbitrage)
Expired    (4) -- swept by cleanupExpiredBids or marked on execute attempt
```

Bids are **hard-deleted** on close: `_closeBid` does `delete bidRegistry[bidId]` so reading `bidRegistry[bidId]` after close returns a zeroed struct (all fields zero, `status == None`). The discovery indexes (`tokenToBids`, `userToBids`) are also cleaned up via O(1) swap-pop. The bid lifecycle events (`BidCreated`/`BidCancelled`/`BidExecuted`/`BidExpired`/`ArbitrageExecuted`) are the canonical history layer — off-chain indexers must consume events for closed-bid lookups; storage reads will not return historical bids.

### Checking Bid Validity

```js
const [isValid, code] = await factory.isBidValid(bidId);
```

`BidValidityCode` enum:

| Code | Value | Meaning |
|---|---|---|
| `Valid` | 0 | Bid is active, unexpired, and funded |
| `NotFound` | 1 | Bid ID does not exist |
| `NotActive` | 2 | Bid exists but is Cancelled/Executed/Expired |
| `Expired` | 3 | Active but past its expiry timestamp |
| `InsufficientHbar` | 4 | Stash has less HBAR than the bid requires |
| `InsufficientLazy` | 5 | Stash has less $LAZY than the bid requires |

Batch validation:

```js
const [validBids, codes] = await factory.validateBids([bidId1, bidId2, bidId3]);
```

### Cancelling a Bid

```js
// From the stash (owner calls stash.cancelBid)
await stash.cancelBid(bidId);

// Or directly on the factory (bid owner or their stash can call)
await factory.cancelBid(bidId);
```

### Cleaning Up Expired Bids

Expired bids are not auto-pruned. Anyone can call `cleanupExpiredBids` to sweep them:

```js
const tx = await factory.cleanupExpiredBids([bidId1, bidId2, bidId3]);
// Returns the count of bids that were actually expired and cleaned
```

This is a public-good function -- callers pay gas but keep the indexes clean for everyone.

## Trade Execution

### Direct Bid Acceptance (executeAgainstBid)

A seller who holds an NFT matching a bid can accept it directly:

```
Seller -> Factory.executeAgainstBid(bidId, nftToken, serial)
    Factory -> LST.createTradeOnBehalf(seller, token, stash, serial, price, ...)
    Factory -> Stash.executeTrade(tradeId, hbarAmount, lazyAmount)
        Stash -> LST.executeTrade{value: hbarAmount}(tradeId)
            LST: seller receives HBAR/LAZY, NFT moves seller -> LST -> stash
    Factory: bid transitions to Executed, removed from indexes
```

Requirements:
- Seller must have approved (via HTS allowance) the LST contract for the NFT
- Bid must be Active, unexpired, and funded
- Serial must match bid's serial filter
- Token must match bid's target collection

### Listing NFTs from a Stash

Users can list NFTs held inside their stash without withdrawing first:

```js
// stash.createTrade routes through factory.createTradeOnBehalfOfStash -> LST.createTradeOnBehalf
const tradeId = await stash.createTrade(
    tokenAddress,
    buyerAddress,   // address(0) for open market
    serialNumber,
    tinybarPrice,
    lazyPrice,
    expiryTime
);
```

## Arbitrage

### How It Works

Arbitrage matches a resting bid (at price B) against an existing open-market LST trade (at price A, where A < B). The spread (B - A) is captured and split between the arbitrageur and the protocol.

```
Arbitrageur -> Factory.executeArbitrage(bidId, existingTradeId, minProfit)
    Factory: validates bid + trade, checks self-arb block, computes spread
    Factory -> Stash.executeTrade(existingTradeId, tradePrice, ...)
        Stash -> LST.executeTrade{value: tradePrice}(existingTradeId)
            LST: trade seller receives HBAR, NFT moves to stash
    Factory -> Stash.arbitrageSettle(bidId, tradeId, spread, 0)
        Stash: transfers spread HBAR to factory, emits StashArbSettled
    Factory: credits pendingArbProfit[arbitrageur] + pendingProtocolProfit
    Factory: bid transitions to Executed
```

### Self-Arbitrage Protection

Three checks block wash trading:

1. `msg.sender != bid.user` -- the arbitrageur cannot be the bidder
2. `msg.sender != trade.seller` -- the arbitrageur cannot be the seller
3. `bid.user != trade.seller` -- the bidder and seller cannot be the same person

### Profit Split & Governance

- Default split: 50/50 (`arbitragePayoutBps = 5000`)
- The owner can propose a new split via `setArbitragePayoutBps(newBps)`
- A 48-hour timelock must elapse before `executeArbPayoutBpsChange()` applies the change
- `executeArbPayoutBpsChange` is permissionless once the ETA is reached

### Claiming Profits

```js
// Arbitrageur claims their accrued profit
await factory.claimArbProfit();

// Factory owner withdraws protocol profit
await factory.withdrawProtocolProfit(recipientAddress, amount);
```

### Stash-Side Settlement Cap

The stash enforces `ARB_SETTLE_MAX_BPS = 7500` (75%) on any single `arbitrageSettle` call. Even if the factory has a bug, it cannot drain more than 75% of the stash's HBAR balance in one transaction.

### minAcceptablePrice

Bidders set `minAcceptablePrice` when creating a bid to guard against surprise-cheap arbitrage matches. If the trade's tinybar price is below this floor, the arbitrage reverts with `ArbitrageProfitInsufficient`. Set to 0 to accept any trade price.

## Discovery Queries

### Paginated Views

| Function | Returns | Notes |
|---|---|---|
| `getBidsForToken(token)` | `bytes32[]` | All bid IDs for a collection (unbounded -- use paginated version for large sets) |
| `getBidsForTokenPaginated(token, offset, limit)` | `bytes32[]` | Paginated. `limit` must be in (0, 200]. |
| `getBidsForTokenSerialPaginated(token, serial, offset, limit)` | `(bytes32[] matches, uint256 nextOffset)` | Cursor-based. Pass `nextOffset` as the next call's `offset`. |
| `getUserBids(user)` | `bytes32[]` | All bid IDs for a user |
| `getTokenBidCount(token)` | `uint256` | Active bid count for a token |
| `getTotalBidCount()` | `uint256` | Lifetime bid counter |

### Stash Snapshot

One call to render a "your stash" dashboard:

```js
const [stash, deployed, hbarBalance, lazyBalance, activeBidIds] =
    await factory.getStashSnapshot(userAddress);
```

If the stash is not deployed yet, `stash` returns the predicted CREATE2 address, balances are 0, and `activeBidIds` is empty.

### Mirror Node Patterns

With deterministic stash addresses, you can query balances and NFT holdings directly from the mirror node without any contract call:

```js
const stashAddress = predictStashAddress(factoryAddr, implAddr, userAddr);
const evmAddress = stashAddress.toLowerCase();

// HBAR balance
const balanceResp = await fetch(
    `https://testnet.mirrornode.hedera.com/api/v1/contracts/${evmAddress}`
);

// NFT holdings
const nftResp = await fetch(
    `https://testnet.mirrornode.hedera.com/api/v1/accounts/${evmAddress}/nfts`
);

// $LAZY balance
const lazyResp = await fetch(
    `https://testnet.mirrornode.hedera.com/api/v1/tokens/${LAZY_TOKEN_ID}/balances?account.id=${accountId}`
);
```

Allow up to 5 seconds for mirror node propagation after consensus transactions.

## Sovereignty & Migration

### Rescue Functions

Every stash has three emergency escape hatches that bypass normal withdrawal logic:

| Function | Asset | Notes |
|---|---|---|
| `rescueHbar(to, amount)` | HBAR | Raw native call. No minimum-balance guard. Any destination. |
| `rescueLazy(to, amount)` | $LAZY | Raw ERC-20 transfer. Any destination. |
| `rescueNFT(token, serial, to, hbarValue)` | Single NFT | Thin wrapper around `moveNFTs`. Pass `1` for `hbarValue` (custody hop). |

All rescue functions are `onlyOwner`. They exist for when the normal withdraw path is blocked for any reason.

### Factory Detachment

```js
await stash.detachFromFactory();
// Emits FactoryDetached(owner, formerFactory)
```

After detachment:
- `factory` is set to `address(0)`
- All `onlyFactory` functions revert permanently
- Bidding, trade creation via factory, and arbitrage settlement are disabled
- `withdrawHbar`, `withdrawLazy`, `withdrawNFTs`, and all rescue functions continue to work
- The stash becomes a pure vault under the owner's control

**This is irreversible.** A detached stash cannot be re-attached. A new stash under any factory will live at a different CREATE2 address.

### Migration Runbook

When a new factory is deployed:

1. New factory is deployed with a fresh `BidderContract` implementation. Users are notified.
2. User calls `detachFromFactory()` on their old stash. The old stash becomes inert.
3. User calls `withdrawHbar`, `withdrawLazy`, `withdrawNFTs` to drain the old stash. Falls back to rescue functions if any withdraw path reverts.
4. User calls `deployStashFor(msg.sender)` on the new factory to get a fresh stash.
5. User re-associates collections and re-deposits funds.

There is no automatic migration, no beacon proxy, no admin upgrade path.

## Allowances & Associations

### For Bidders (Stash Users)

| Action | What's Needed |
|---|---|
| Fund stash with HBAR | Direct `TransferTransaction` to stash address |
| Fund stash with $LAZY | ERC-20 transfer to stash address (LAZY auto-associated on init) |
| Create a bid | Stash auto-associates the target NFT collection |
| Withdraw NFT | Owner's account must be associated with the NFT collection |

### For Sellers (Accepting Bids)

| Action | What's Needed |
|---|---|
| Accept a bid (`executeAgainstBid`) | HTS NFT allowance granted to the LST contract for the specific serial |
| Receive HBAR payment | No special setup needed |
| Receive $LAZY payment | Must be associated with $LAZY token |

### For Arbitrageurs

| Action | What's Needed |
|---|---|
| Execute arbitrage | No allowances needed -- all fund movements are contract-internal |
| Claim profit | No allowances needed -- `claimArbProfit()` sends HBAR to `msg.sender` |

## Events Reference

### BidderContractFactory Events

| Event | Indexed Fields | Data Fields | When |
|---|---|---|---|
| `StashDeployed(user, stash, deployer)` | user, stash, deployer | -- | Stash clone deployed |
| `BidCreated(bidId, user, token, details)` | bidId, user, token | BidDetails struct | Bid registered |
| `BidCancelled(bidId, user)` | bidId, user | -- | Bid cancelled by owner |
| `BidExecuted(bidId, executor, tradeId, arbitrageProfit)` | bidId, executor | tradeId, arbitrageProfit | Bid matched (direct or arb) |
| `BidExpired(bidId, user)` | bidId, user | -- | Bid expired (on execute attempt or cleanup) |
| `ExpiredBidsCleanup(cleaner, cleanedCount)` | cleaner | cleanedCount | Batch cleanup completed |
| `TradeCreatedFromStash(tradeId, stash, seller, token, serial)` | tradeId, stash, seller | token, serial | NFT listed from stash |
| `ArbitrageExecuted(bidId, tradeId, arbitrageur, arbCut, protocolCut)` | bidId, tradeId, arbitrageur | arbCut, protocolCut | Arbitrage completed |
| `ArbProfitClaimed(arbitrageur, amount)` | arbitrageur | amount | Arb profit withdrawn |
| `ProtocolProfitWithdrawn(to, amount)` | to | amount | Protocol profit withdrawn |
| `ArbPayoutBpsChangePending(newBps, eta)` | -- | newBps, eta | Timelock proposed |
| `ArbPayoutBpsChanged(newBps)` | -- | newBps | Timelock applied |

### BidderContract (Stash) Events

| Event | Indexed Fields | Data Fields | When |
|---|---|---|---|
| `FactoryDetached(owner, formerFactory)` | owner, formerFactory | -- | Stash detached |
| `StashArbSettled(bidId, tradeId, hbarAmount, lazyAmount)` | bidId, tradeId | hbarAmount, lazyAmount | Arb settlement on stash side |

### LazySecureTrade Events (relevant to v0.3 flows)

| Event | Indexed Fields | Data Fields | When |
|---|---|---|---|
| `TradeCreated(seller, buyer, token, ...)` | seller, buyer, token | serial, prices, expiry, nonce | Trade listed |
| `TradeCompleted(seller, buyer, token, ...)` | seller, buyer, token | serial, nonce | Trade executed |
| `TradeCancelled(seller, token, ...)` | seller, token | serial, nonce | Trade cancelled |
| `FactoryAuthorized(factory, authorized)` | factory | authorized | Factory authorization changed |
| `PlatformFeeCollected(seller, buyer, hbarFee, effectiveFeeRate)` | seller, buyer | hbarFee, effectiveFeeRate | HBAR fee charged on trade |

### Indexer Tips

- Subscribe to the factory address for all bid lifecycle events.
- Subscribe to a user's deterministic stash address for `StashArbSettled` and `FactoryDetached`.
- For balance monitoring, query the stash address directly on the mirror node -- no events needed for deposits (EOA to stash transfers are visible as standard HBAR/token transfers).
- `BidCreated` includes the full `BidDetails` struct in its data payload -- decode it to get all bid parameters without a follow-up `bidRegistry` call.
