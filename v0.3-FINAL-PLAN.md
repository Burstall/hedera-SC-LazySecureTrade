## Framing & Terminology

### v0.3 is an active design, not a ship-prep sprint
Everything here is redesign-friendly. `executeArbitrage` is a WIP stub by intent, the BidderContract is a draft, and contract APIs can still change. Testnet state is disposable (greenfield).

### Royalty handling — NOT "royalty defeat"
The 1-tinybar parameter in `TokenStakerV2.moveNFTs` / `batchMoveNFTs` is **internal custody plumbing**, not royalty evasion. Hedera requires both parties to sign a cryptoTransfer unless one side is a contract holding the NFT. The platform uses a 2-step transfer (seller → LST → buyer) and the 1-tinybar value marks intermediate custody hops as non-sale internal moves so they don't get charged royalties on bookkeeping transfers. **The actual creator royalty is enforced on the real sale leg.** Rename all references from "defeat" to "transit" / "custody hop" and document the pattern in NatSpec + `SECURITY.md`.

### "Stash" not "honeypot"
Per-user bidder contracts are called **stash**. New code, events, and docs use stash terminology. Contract class name (`BidderContract`) stays for this branch to avoid mid-flight rename; new surface uses `stash`.

### Hedera-specific facts that reshape the design
- **No MEV**: Hedera consensus orders by timestamp — no mempool, no front-running, no sandwich attacks. Arbitrage design drops all MEV-defense patterns (commit-reveal, slippage-as-MEV-guard, cooldowns-for-MEV-fairness).
- **CREATE2 cannot pre-fund**: Unlike Ethereum, you cannot send HBAR to an EVM address on Hedera before an account exists there. Clients can still *predict* the CREATE2 address (for mirror-node queries) but cannot pre-fund before deployment.
- **50 subcalls/tx ceiling**: any new hot-path HTS precompile call competes with batch operation headroom. LSH listing gas refund was declined for this reason — the subcall budget is preserved for bulk trades.

### LSH utility — where it lives
LSH holder value already complete via:
1. **Platform fee tier discounts** in LST (Gen1 100% / Mutant 75% / Gen2 50%)
2. **$LAZY listing fee exemption** via `areAdvancedTradesFree()`
3. **LAZY Trade Lotto odds** — external, event-driven, off-repo
4. **Future payment splitter** — separate Hedera project; will consume LST events for fee distribution

Do NOT add new LSH-holder features inside LST/Factory/Stash. Route via external event indexers or separate contracts.

### Package E — Critical Bug Pack
**Risk**: low-medium (modifying hot paths). **Effort**: ~1 day including manual review.

#### E1. `TokenStakerV2.batchTokenAssociate` strict-SUCCESS bug
**File**: `contracts/TokenStakerV2.sol:176-184`
**Current**:
```solidity
function batchTokenAssociate(address[] memory tokenIds) public {
    int256 response = HederaTokenService.associateTokens(address(this), tokenIds);
    if (response != HederaResponseCodes.SUCCESS) {
        revert BatchAssociationFailed();
    }
}
```
**Problem**: Reverts on `TOKEN_ALREADY_ASSOCIATED_TO_ACCOUNT`, bricking any re-association attempt. Inconsistent with `tokenAssociate` (line 162) which tolerates it. Only `safeBatchTokenAssociate` is currently safe to call.
**Fix**:
```solidity
function batchTokenAssociate(address[] memory tokenIds) public {
    int256 response = HederaTokenService.associateTokens(address(this), tokenIds);
    if (!(response == SUCCESS || response == TOKEN_ALREADY_ASSOCIATED_TO_ACCOUNT)) {
        revert BatchAssociationFailed();
    }
}
```

#### E2. LDR try/catch defensive wrap in `getLSHTokenTier`
**File**: `contracts/LazySecureTrade.sol:791-822`
**Problem**: `getLSHTokenTier` makes 3 LDR calls (`getSerialsDelegatedTo` for Gen1, Mutant, Gen2). LDR is immutable and known-buggy. If any call reverts, the entire trade execution path bricks for the affected seller. User explicitly flagged LDR as "immutable, has known issues, we live with them."
**Fix**: Introduce private helper `_safeGetDelegatedLength` that wraps the LDR call in try/catch, returning 0 on failure (fallback = user gets base tier):
```solidity
function _safeGetDelegatedLength(address _user, address _token) private view returns (uint256) {
    try lazyDelegateRegistry.getSerialsDelegatedTo(_user, _token) returns (uint256[] memory delegatedSerials) {
        return delegatedSerials.length;
    } catch {
        return 0;
    }
}
```
Then rewrite `getLSHTokenTier` to use the helper at each tier check. Bytecode cost: ~150-250 bytes. Verify LST stays under 24,576.

#### E3. BidderContract LAZY allowance target bug
**File**: `contracts/BidderContract.sol:322-332`
**Current**:
```solidity
function executeTrade(...) external payable onlyFactory nonReentrant {
    if (lazyAmount > 0) {
        IERC20(lazyToken).approve(lazySecureTradeAddress, lazyAmount); // WRONG
    }
    ILazySecureTrade(lazySecureTradeAddress).executeTrade{value: hbarAmount}(tradeId);
}
```
**Problem**: LST's `_processLazyPayment` (line 1444) calls `lazyGasStation.drawLazyFromPayTo(buyer, lazyPrice, 0, seller)`. LazyGasStation's `drawLazyFromPayTo` then checks `IERC20(lazyToken).allowance(_user, address(this))` — meaning **the allowance must be on LazyGasStation, not LST**. Confirmed against `LazyGasStation.sol` source (github.com/lazysuperheroes/hedera-SC-LAZY-Farms).
**Fix**: Approve `address(lazyGasStation)` instead of `lazySecureTradeAddress`. The `lazyGasStation` field is inherited from `TokenStakerV2` and set in `initContracts()` during `initialize()`.
```solidity
if (lazyAmount > 0) {
    IERC20(lazyToken).approve(address(lazyGasStation), lazyAmount);
}
```

### Phase 3 — Arbitrage Redesign
**Blocked by**: Phase 2. **Effort**: ~2 days.

Remove:
- Current `executeArbitrage` stub (lines 700-740)
- `ArbitrageNotImplemented` error
- `factoryWithdrawHbar` / `factoryWithdrawLazy` on BidderContract (replaced by scoped arbitrage settlement path)

Add to `BidDetails` struct:
- `uint256 minAcceptablePrice` — bidder's floor; arbitrage reverts if ask < floor

Add to BidderContractFactory:
- `function executeArbitrage(bytes32 bidId, bytes32 askTradeId, uint256 minProfit) external nonReentrant returns (uint256 profit)`
  - Load bid from registry; revert if not found or expired
  - Load trade from LST; validate exists and not expired
  - **Wash-trade block**: `require(msg.sender != bid.user && msg.sender != trade.seller && bid.user != trade.seller, SelfArbitrageBlocked)`
  - **Price floor**: `require(trade.tinybarPrice >= bid.minAcceptablePrice, BelowPriceFloor)`
  - Calculate spread = `bid.hbarAmount - trade.tinybarPrice`
  - **Min profit check**: `require(spread >= minProfit, InsufficientProfit)`
  - Split spread: `arbCut = spread * arbitragePayoutBps / 10_000`, `protocolCut = spread - arbCut`
  - Pre-call snapshot: `bytes32 preSnapshot = keccak256(abi.encode(bidRegistry[bidId]))`
  - Execute bid-against-ask via stash (scoped settle)
  - Post-call verify: `require(keccak256(abi.encode(bidRegistry[bidId])) == preSnapshot || bidRegistry[bidId].user == address(0), RegistryDriftDetected)`
  - Credit `pendingArbProfit[msg.sender] += arbCut`
  - Credit `pendingProtocolProfit += protocolCut`
  - Remove bid from registry
  - Emit `ArbitrageExecuted(bidId, askTradeId, msg.sender, arbCut, protocolCut)`
- `function claimArbProfit() external nonReentrant` — arbitrageur pulls their credited profit
- `function withdrawProtocolProfit() external onlyOwner` behind timelock
- `function setArbitragePayoutBps(uint256)` — owner-tunable, behind timelock

Add to BidderContract (stash):
- `function arbitrageSettle(bytes32 bidId, bytes32 tradeId, uint256 hbarAmount, uint256 lazyAmount) external onlyFactory nonReentrant` — scoped replacement for `factoryWithdraw*`. Executes the trade on LST (the same path `executeTrade` uses) PLUS transfers the spread to the factory. Bounded by (bidId, tradeId) context; no unbounded amount parameter. **Emit stash-side event**: `StashArbSettled(bidId, tradeId, hbarAmount, lazyAmount)` — confirmed per user's round-3 feedback that stash-side events are worth emitting especially with deterministic addressing.
- Remove `factoryWithdrawHbar` / `factoryWithdrawLazy` entirely.

Notes:
- No `allowArbitrage` per-bid opt-out flag (user rejected — UX concern)
- No seller allow/deny list (user rejected — bytecode + UX)
- No commit-reveal (Hedera has no MEV)
- No cooldown window (no MEV, and seller already has direct-accept priority via `executeAgainstBid`)
- Wash-trading block is the only anti-abuse guard needed

## Open Questions

1. **Arbitrage timelock scope**: Should `setArbitragePayoutBps` and `withdrawProtocolProfit` timelock use a shared external `TimelockController` (OZ) or a minimal inline delay mapping? External Timelock is cleaner but adds a contract; inline is ~100 bytes and is enough for a simple setter.

2. **`pendingArbProfit` claim gas**: HBAR claim is `Address.sendValue`. Is there any concern about a contract arbitrageur receiving HBAR failing (e.g., via reverting fallback)? Suggest adding a secondary `sweepUnclaimedProfit(address recipient)` owner function after a long delay to recover stuck profits.

3. **Stash event emission volume**: With deterministic addresses, users can monitor their stash directly via mirror node. Stash-side events are still useful for arbitrage settlement trails (per user feedback) — but should regular `executeTrade` → `executeAgainstBid` ALSO emit stash-side? I'd lean yes for consistency with arbitrage path, but it adds ~200 bytes bytecode. Confirm after P0 measurements tell us the subcall/gas budget.

4. **`retrieveLazy` reframing**: The function exists as an owner emergency recovery path. Should it be deleted entirely (cleaner) or kept with better docs? Keeping it is ~80 bytes; deleting means no recovery path if LAZY accidentally gets stuck in LST via an unexpected flow. Recommend keeping but documenting properly.

5. **P0 user address for stash tests**: Should the test use the operator account or create a fresh account via `accountCreator.js`? Fresh account gives cleaner isolation but costs HBAR for account creation. Operator is simpler but leaks state across runs.
